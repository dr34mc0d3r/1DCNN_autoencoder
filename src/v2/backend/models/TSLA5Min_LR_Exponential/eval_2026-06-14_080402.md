## Suggested settings for this data

### 1. gamma=0.95 kills the LR after ~45 epochs — primary issue

**Current → Suggested**: `gamma` 0.95 → **0.99** (keeping `initial_lr` at 1e-4)

**Why**: With gamma=0.95 from 1e-4, the learning rate crosses below 1e-5 after only ~45 epochs:

```
epoch  45:  1e-4 × 0.95^45  ≈ 1e-5    ← LR falls below useful threshold here
epoch 100:  1e-4 × 0.95^100 ≈ 5.9e-7
epoch 173:  1e-4 × 0.95^173 = 1.40e-8  ← matches stored final_lr exactly
```

The model trained 173 epochs but had effectively zero weight updates from epoch ~50 onward. The plateau guard fired correctly — it detected that val_loss stopped improving — but the root cause was the LR being dead, not the model having genuinely converged.

With **gamma=0.99** from 1e-4:
```
epoch 173:  1e-4 × 0.99^173 ≈ 1.75e-5  (still learning at the current plateau point)
epoch 500:  1e-4 × 0.99^500 ≈ 6.6e-7   (acceptable floor at full epoch budget)
```

The model would have active updates for 200+ epochs and the plateau guard would fire only if it genuinely converged, not from LR starvation.

---

### 2. guard_overfit_ratio=10 will never fire in practice

**Current → Suggested**: `guard_overfit_ratio` 10 → **2.0–2.5**

**Why**: The overfit detector fires when `val_loss / train_loss > overfit_ratio`. At current values (train=0.47, val=0.59), the ratio is 1.25×. For the 10× threshold to trigger, val_loss would need to reach 4.7 — which can't happen in practice on a normalized reconstruction task. A threshold of 2.0–2.5 would catch meaningful divergence (val loss 2× train) while tolerating the expected small gap. The current 25% gap is healthy and well within a 2× threshold.

---

### 3. vol_return outlier at 1836× — clip before retraining

**Current**: `vol_return` pre-scale range = -1.0 to **1836.1** (mean=1.87, std=28.0)

**Why**: A single bar with 1836× normal volume will produce an extreme post-scale value in any window that contains it. RobustScaler's IQR-based parameters are unaffected, but the scaled value will be hundreds of standard deviations above the median. The autoencoder will produce large gradients trying to reconstruct it, which can slow convergence or cause oscillation in the epochs when it's encountered.

`trade_count_ratio` also peaks at 17.5× — same IEX partial-volume artifact.

**Action**: Clip at 99th percentile in `add_features()` before the scaler:
```python
df['vol_return'] = df['vol_return'].clip(upper=df['vol_return'].quantile(0.99))
df['trade_count_ratio'] = df['trade_count_ratio'].clip(upper=df['trade_count_ratio'].quantile(0.99))
```

### 4. KMeans now run — inspect cluster quality before retraining

**Update**: `has_kmeans` changed from `false` to `true` between evaluations. KMeans with n_clusters=8 has been run on the latent space of this model.

**What to check**: The cluster quality directly tells you whether the current model (despite the LR issue) learned useful representations:
- If 8 clusters show clear separation with balanced membership: the model captured meaningful market regimes despite the LR decay, and the LR fix will likely improve further
- If 1–2 clusters dominate (>60% of windows): the latent space is collapsed — the model didn't learn discriminative representations; the LR fix is essential
- If cluster membership looks random (even distribution, no temporal coherence): underfitting — the model learned to reconstruct mean patterns only

The cluster distribution is visible in the app's latent space view. Use this to decide whether the existing model weights are worth examining, or whether retraining (with the LR fix) should be the priority.
