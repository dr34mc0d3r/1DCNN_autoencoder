## Suggested settings for this data

### 1. gamma=0.95 kills the LR after ~45 epochs — the primary issue

**Current → Suggested**
- `gamma`: 0.95 → **0.99** (keeping initial_lr at 1e-4)

**Why**: With gamma=0.95 from 1e-4, the LR crosses below 1e-5 after only ~45 epochs:

```
1e-4 × 0.95^45 ≈ 1e-5  (crossover point)
1e-4 × 0.95^100 ≈ 5.9e-7  (essentially zero)
1e-4 × 0.95^173 = 1.40e-8  (matches final_lr exactly)
```

The model ran 173 epochs but had no meaningful weight updates after epoch ~50. Epochs 50–173 were pure compute waste. The plateau guard correctly detected the symptom (no val improvement for 10 epochs), but the root cause is the LR being dead, not the model having converged.

With **gamma=0.99** from 1e-4:
```
1e-4 × 0.99^173 ≈ 1.75e-5  (still learning at the plateau point)
1e-4 × 0.99^500 ≈ 6.6e-7   (reasonable floor at end of budget)
```

This keeps the LR in a productive range for at least 200+ epochs and gives the model a real chance to use the full 500-epoch budget. If it plateaus, it will be because the model genuinely converged, not because the optimizer was starved.

Alternative: raise `initial_lr` to 1e-3 with gamma=0.95:
```
1e-3 × 0.95^45 ≈ 1e-4   (still viable at epoch 45)
1e-3 × 0.95^100 ≈ 5.9e-6  (marginal by epoch 100)
```
This buys another 45 epochs of effective learning but still dies by epoch ~90. The gamma=0.99 approach is cleaner for a 500-epoch budget.

### 2. guard_overfit_ratio=10 will never fire in practice

**Current → Suggested**
- `guard_overfit_ratio`: 10 → **2.0–2.5**

**Why**: The overfit detector fires when `val_loss / train_loss > overfit_ratio`. At current train=0.47, val=0.59, the ratio is 1.25×. For the 10× threshold to fire, val_loss would need to reach 4.7 — which would only happen during catastrophic failure, not normal overfitting. A ratio of 2.0–2.5 (val loss 2–2.5× train) catches meaningful divergence while still tolerating the expected slight train/val gap in a reconstruction model. The current 24.5% gap is healthy; catching it at 2–2.5× gives useful early warning.

### 3. vol_return outlier at 1836× — clip before training

**Current**: `vol_return` range = -1.0 to **1836.1** (mean=1.87, std=28.0)

**Why**: One bar in 108,391 had 1836× the rolling average volume. RobustScaler's parameters (median, IQR) are unaffected by this outlier, but after scaling this data point will be extreme. The autoencoder will see it and try to reconstruct it, producing large gradients in any window containing it.

This is likely an Alpaca IEX data artifact (free-tier partial volume reporting). `trade_count_ratio` also reaches 17.46 (vs normal ~1.0), same artifact.

**Action**: Clip in `add_features()`:
```python
df['vol_return'] = df['vol_return'].clip(upper=df['vol_return'].quantile(0.99))
df['trade_count_ratio'] = df['trade_count_ratio'].clip(upper=df['trade_count_ratio'].quantile(0.99))
```
